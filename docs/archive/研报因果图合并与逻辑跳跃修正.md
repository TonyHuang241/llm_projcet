# 以证据拼图，用路径拆解逻辑跳跃

把逐段三元组拼成研报级大图，关键不在于把相似节点合并得更狠，而在于把"合并"拆成几种带来源标记的动作。抽取期，用一份由报告自己归纳的"规范变量表＋一句定义"统一命名，LINK-KG 式缓存在长文档上把节点重复率从 36.01% 降到 17.78%。去重期，用确定性分块、"从候选中选一个或都不选"的 LLM 判定和决策缓存，替换不稳定的 k-means。连边期，用同义软边、部分-整体/上下位等定义性边，以及"必须引用段落"的跨分量桥接，代替强行合并；CrossAug 只多花约 8% 的调用，新三元组抽检 84% 正确。跨研报阶段，只有多篇报告一致时才把软边提升为合并。逻辑跳跃的修正要分清两件事。图论方法（传递约简加路径符号积）只能找出"已被其他路径覆盖"的捷径边；报告里根本缺中介的跳跃，只能靠抽取时标注的论断类型、节点层级跨度等可观测信号发现，因为让 LLM 判断"这条边是否直接"恰恰最不可靠：它会把 40% 的间接关系判成直接边，其中八成以上给出 ≥80% 的口头置信度。修复顺序是：先在本报告其他段落找替代路径；再到跨研报聚合图里检索符号积一致、支持度足够的 2–4 跳链条；最后才让 LLM 在封闭候选中做选择。每一跳都用原文检索加 NLI 核验，并按 explicit / report_supported / corpus_supported / llm_inferred 分级标注。原来的跳跃边不删，改标为"概括边"。整套方案不需要预设估值骨架，骨架从语料频次中长出来，每一跳都能回溯到具体研报句子。代价有两个：一部分研报会保留断开的子图；目前没有任何中文研报基准能量化这些方法的准确率，需要自建几百条标注来校准阈值。

## 抽取期统一命名，长文档重复节点可减半

逐段抽取产生断裂子图和重复节点，根源在于每一段都在独立命名。同一个"海外销量"，第 3 段叫"出口量"，第 17 段叫"海外出货"，事后去重只能补救一部分。最有力的证据来自在抽取时注入一份不断累积的别名表的工作。LINK-KG 顺序处理各 chunk：Mapping-LLM 维护一份缓存，记录"别名→规范名"和每个规范实体的一句描述；Resolve-LLM 再带着最终缓存改写每个 chunk。在超过 2500 词的长文档上，节点重复率从 GraphRAG 的 **36.01%**、CORE-KG 的 26.10% 降到 **17.78%** ([LINK-KG](https://arxiv.org/abs/2510.26486))。EDC 的 refinement 把上一轮的实体和关系连同自然语言定义放回抽取 prompt，WebNLG 上 F1 从 0.746 升到 **0.794**，REBEL 从 0.506 升到 0.559，第二轮迭代收益很小 ([EDC](https://arxiv.org/abs/2404.03868))。KGGen 也是两步：先抽实体，再只在这些实体之间抽关系，作者明确说这样设计是为了实体一致 ([KGGen](https://arxiv.org/abs/2502.09956))。这些结果的适用范围有限：LINK-KG 只评估了 16 篇英文法律文书，单人标注，没有金标准；也没有任何工作在中文金融文本上量化过"注入词表"对重复率的影响。

词表的用法有一个容易踩的坑。iText2KG 把全局实体集合作为关系抽取的上下文后，计算机领域三元组精度从 **0.94 掉到 0.83**，音乐领域从 0.90 掉到 0.81，原因是全局实体诱导模型连出原文没写的关系 ([iText2KG](https://arxiv.org/abs/2409.03284))。所以词表只能约束"怎么叫"，不能提示"连什么"。这一点对逻辑跳跃问题尤其要紧：词表里一旦列着"公司估值"，模型就会被鼓励把段落里的任何因素直接连到估值上。词表每一项写成"名称＋一句定义"，定义写清度量对象、口径（总量/分地区/分业务）以及是比率还是绝对量；EDC 的 definition 和 LINK-KG 的 auxiliary description 都表明，带定义比只给名称更利于后续判重。变量名统一用"水平量"，如"海外销量"而不是"海外销量下滑"，方向只由正负号表达。sd-ai 基准里，gpt-4o 找全了链接，却在"减少类"变量名的极性上出错 ([sd-ai benchmark](https://web3.arxiv.org/pdf/2503.15580))。

长研报不做全文抽取，有充分的实证依据，"全文抽取误判更多"的担忧成立。NoLiMa 测试的 13 个标称支持 128K 的模型中，有 **11 个在 32K 时跌到短上下文基线的一半以下**，GPT-4o 从 99.3% 降到 69.7% ([NoLiMa](https://arxiv.org/abs/2502.05167))。Chroma 的 Context Rot 实验显示，约 300 token 的聚焦输入在所有模型家族中都胜过约 113k token 的全量输入，而且单个干扰项就会拉低准确率，干扰内容还会混进幻觉答案 ([Context Rot](https://www.trychroma.com/research/context-rot))。研报里成片的营收、毛利率、分业务增速，彼此都是干扰项，整篇抽取最典型的错误就是把 A 业务的驱动因素错配给 B 业务。另一方面，文档级关系抽取中，GPT-4-turbo 的跨句 F1 只有 **7.43**，约为句内 F1（14.52）的一半；先用分类器滤掉无关实体对后，跨句 F1 升到 **27.30** ([LMRC](https://arxiv.org/html/2408.13889))。可见跨段关系抽不出来，瓶颈在候选空间太大，并不是模型做不到。折中方案由此而来：不给每段喂全文，而是给每段一个小而精的全局候选集。

| 轮次 | 输入 | 输出 | LLM 调用 |
|---|---|---|---|
| Pass 0 规则解析 | PDF/Markdown | 章节标题树、段落 ID | 0 |
| Pass 1 略读 | 每章标题＋段首句（长文先做章级 gist，再在 gist 上归纳） | 论证提纲（主张、3–8 条论点）、规范变量表（名称＋定义＋出现段落） | 1 至"章节数＋1" |
| Pass 2 逐段抽取（并行） | 提纲＋变量表＋标题路径＋上一段摘要＋本段原文 | 三元组＋evidence_span＋claim_type＋compressed 标记；新变量须附定义 | N（每加 1 轮 gleaning 再＋N） |
| Pass 3 整合 | 只读三元组和变量表，不回读全文 | 判重、类型化连边、跨分量桥接、跳跃标记 | 与候选数成正比 |

分层方法有旁证支持。Chain-of-Agents 让每个 worker 只读 8k 上下文、由 manager 汇总，在多个长文档任务上胜过 200k 全文输入 ([Chain-of-Agents](https://proceedings.neurips.cc/paper_files/paper/2024/hash/ee71a4b14ec26710b39ee6be113d7750-Abstract.html))。Anthropic 给每个 chunk 前置 50–100 token、说明"本块在全文中的位置"，检索失败率降低 35%–67% ([Contextual Retrieval](https://www.anthropic.com/news/contextual-retrieval))，不过这组证据来自检索任务，不是关系抽取。GraphRAG 发现，600 token 的块抽到的实体引用几乎是 2400 token 块的两倍；它用 gleaning（先问模型是否有遗漏，再让它补抽）弥补大块召回的损失 ([GraphRAG](https://arxiv.org/abs/2404.16130))。把 gleaning 的追问改成"本段是否有被跳过的中间变量"，就是在抽取端预防跳跃成本最低的手段。全文输入只适合输出很小的 gist 型任务，比如 Pass 1 的提纲和词表；细粒度三元组坚持用短上下文抽取。此前观察到 Haiku 整篇抽取短报告时图更连通，这和上述结论不矛盾：短报告本来就在模型有效范围内。可以按长度分流，短报告走"整篇抽取＋逐段核验"，长报告走四轮流水线，分流阈值用自有样本标定。顺序缓存（LINK-KG、CoA 式累积记忆）和"Pass 1 词表＋并行抽取"之间，取舍在一致性和延迟。顺序缓存命名最一致，还能吸收后文给出的定义；但 60 段就是 60 次串行调用，早期错误也会沿缓存传下去。并行方案多花一次调用换来并行，可以再配一次 LINK-KG 式回扫，修正早期的映射。

## 用确定性分块和"选一个或都不选"取代 k-means 判重

现有的"BGE＋k-means＋LLM 提议＋LLM 复核"和 KGGen 几乎同构。KGGen 用 S-BERT 嵌入，k-means 切成每簇 128 项，簇内取 top-16 近邻交给 LLM 判重 ([KGGen](https://arxiv.org/abs/2502.09956))。它只报告了规模缩减（实体 −22.4%、边 −23%），没有报告合并正确率。作者自己承认过合并和欠合并问题仍未解决，还点名金融等领域可能超出通用 LLM 的知识。这类结构的不稳定是固有的：候选集合由 k-means 分区决定，k 值或随机初始化一变，同一对节点就会落进不同的簇、在不同的上下文中被判定，结果随之漂移。

第一步，把召回改成确定性的。Graphiti 的开源代码在调用 LLM 之前先做一轮确定性消解：规范化后精确匹配；低信息的短名用字符熵门控；用 3-gram MinHash＋LSH 召回，Jaccard ≥0.9 才判为匹配；剩下的才交给 LLM ([Graphiti dedup_helpers](https://github.com/getzep/graphiti/blob/main/graphiti_core/utils/maintenance/dedup_helpers.py))。这段代码不能直接照搬：它的模糊匹配会把 `a-z0-9'` 以外的字符替换成空格，中文名会被整个抹掉，全部落到 LLM 分支。中文场景须改用字符 2-gram/3-gram shingle。推荐的替代方案有两种。其一，对"名称：定义"做 BGE 嵌入，同时计算字符 n-gram Jaccard，相似度或 Jaccard 超过阈值才连边，建成 kNN 图后取连通分量作为候选块。其二，用 complete-linkage 凝聚聚类加簇内相似度阈值。AECR 正是用这种方式聚类因果对，它比 k-means 更不容易把语义跨度大的变量链式并到一起 ([AECR](https://arxiv.org/pdf/2608.05205))。嵌入和阈值给定后，分块结果完全确定。

第二步，改判定形式。COLING 2025 的 Match/Compare/Select 研究在 8 个数据集、9 个 LLM 上发现，让模型从候选列表里选出匹配项（或回答"无"）优于逐对判断，一个版本报告平均 F1 **+17.58%**；但真实匹配项在列表中越靠后，准确率掉得越多 ([Match, Compare, or Select](https://arxiv.org/abs/2405.16884))，所以候选要按相似度排序，或打乱多次后投票。LLM-CER 更进一步：把块内记录组成约 9 条、约含 4 个实体的小集合，让 LLM 直接聚类。与成对判断相比，API 调用少 **12–108 倍**，成本低 3–22 倍，准确率持平或略高（Cora 上 0.88→0.90，调用数从 30.23K 降到 0.28K）。集合超过 9–10 条时质量明显下降。它的误聚类护栏用约 10% 的额外时间，把 FP-measure 最多提升 75% ([LLM-CER](https://arxiv.org/abs/2506.02509))。KwikBucks 的相关聚类不限量使用嵌入相似度，只在预算内调用强模型，强模型查询量减少 3.5 倍以上 ([KwikBucks](https://preview.aclanthology.org/fix_video/2023.sustainlp-1.1.pdf))。在此之上再加一张持久的决策缓存：以（规范名 A，规范名 B，定义哈希）为键，记录每次"同一/不同"的判定，后续遇到同一对直接复用。这是消除跨批次漂移最直接的办法，即使块的构成变了，判过的对也不会翻转。如果 LLM 两两判出 A=B、B=C，却又判 A≠C，不要直接做传递闭包，而是把三者作为一个小集合整体重新聚类。已有工作专门利用传递一致性找出误匹配 ([SBBD](https://sol.sbc.org.br/index.php/sbbd/article/view/44035))。

第三步，防止"相似但不同"的概念被误合并，在研报里这比欠合并更危险。EDC 规范化时显式提供"None of the above"选项，匹配不上就新建，人工评估精度 **0.956**；对照组 CESI 把不同关系过度聚到一起，精度只有 0.724 ([EDC](https://arxiv.org/abs/2404.03868))。纯嵌入加编辑距离会把"1963 AFL Draft"和"1963 NFL Draft"并成一组 ([LlamaIndex](https://www.llamaindex.ai/blog/customizing-property-graph-index-in-llamaindex))，换到中文短词就是"毛利率/净利率""出口销量/销量"。经济叙事研究刻意不合并"通胀预期"和"通胀" ([Schmidt et al.](https://arxiv.org/pdf/2506.15041))。落地做法是给每个变量标几个结构槽位：度量类型（绝对量/比率/增速/价格/份额）、口径（总量/分地区/分产品/分业务）、主体（公司/行业/宏观）、所属财务科目。槽位不一致一律禁止合并，改用下一节的部分-整体边或函数关系。另外维护一张很短的财务变量锚点表（营收、毛利率、费用率、归母净利润、EPS、估值倍数等），只用于节点规范化，不规定链条。FinCaKG-Onto 指出，直接依赖原始文本串会在语义薄弱处失效；对齐 FIBO 后，本体一致性达到 95.6% ([FinCaKG-Onto](https://www.itm-conferences.org/articles/itmconf/pdf/2025/10/itmconf_keis2025_01029.pdf))。最后，聚类只用于判重，不要按语义簇拆分因果抽取本身。有研究先做嵌入聚类，再分簇建因果子图，最后两两合并，SHD 明显不如一次性直接提示，原因是语义相似和因果结构并不对应 ([Decomposition does not help](https://citius.gal/en/research/publications/decomposition-does-not-help-evidence-from-semantic-clustering-in-llm-based-causal-graph-discovery/))。

## 合并之外再加三类非因果边，跨段桥接必须引用原文

图拼不起来，很多时候是因为只有一种节点操作（合并）和一种边（正/负因果）。"出口销量"和"销量"不该合并，也不该断开；"中欧贸易摩擦"和"贸易摩擦"是具体与一般的关系；"营业收入"由各分部收入加总而成。把这些都塞进"合并"或"因果"，要么丢失信息，要么写入原文没说过的因果。INDRA 的组装逻辑把陈述之间的关系分成三类：matching（完全重复）、contradiction（同一对节点符号相反）、refinement（一般与具体）。在 refinement 关系下，更具体陈述的证据会间接支持更一般的陈述 ([INDRA World](https://indra-world.readthedocs.io/en/latest/general.html))。HippoRAG 2 在嵌入相似度高于 0.8 的短语节点之间加同义边，不合并节点，借此实现跨段落连通 ([HippoRAG 2](https://arxiv.org/abs/2502.14802))。跨文档合并因果图时，"analogy"策略保留原节点，在上方加一个共同祖先，各图的机制保持不变，代价是节点增多 ([arXiv 2410.06392](https://arxiv.org/abs/2410.06392))。部分-整体关系有现成的形式化：XBRL calculation linkbase 的 summation-item 弧带 +1/−1 权重，负权重表示扣减，把 −1 当成 +1 会算错合计 ([Altova XBRL](https://www.altova.com/manual/XMLSpy/spyenterprise/xsxbrl_basics_creatingrelationshipstwo.html)；[EdgarTools](https://edgartools.readthedocs.io/en/latest/xbrl/guides/calculation-linkbase/))。

| 边类型 | 含义 | 典型来源 | 计入连通性 | 计入因果链 |
|---|---|---|---|---|
| CAUSES(±) | 原文陈述的因果，带符号 | 逐段抽取 | 是 | 是 |
| SAME_AS_CANDIDATE | 未确认的同义，带相似度 | 判重中置信度不足的节点对 | 是 | 否（提升为合并后才算） |
| PART_OF(±1) | 部分→整体，权重表示加总或扣减 | 会计恒等式、"其中/占比/拆分"等表述、共享中心词 | 是 | 单独标注为定义性同向 |
| IS_A | 下位→上位 | 修饰词规则（"中欧贸易摩擦"→"贸易摩擦"）＋LLM 确认 | 是 | 否，但可用来继承语料中的典型链条 |

每条边都带 `provenance ∈ {text_stated, definitional, rule, llm_inferred}` 和支撑段落 ID。比率和绝对量之间是函数关系，不是部分-整体。"毛利率＝毛利/收入"只记在变量表的定义里，不作为因果边写入，以免凭空生成"毛利率↑→利润↑"这类边。部分-整体边的候选应来自规则，而不是让 LLM 自由推断：LLM 对部分-整体关系（meronymy）只有"准语义"水平的掌握 ([arXiv 2504.02395](https://arxiv.org/abs/2504.02395))。规则推断本身也要节制。ai-knowledge-graph 的测试中，规则推断出的边一度占全部边的约 70%，噪声太大，传递规则和词法规则因此默认关闭 ([ai-knowledge-graph](https://github.com/robert-mcdermott/ai-knowledge-graph))。

跨分量桥接的直接先例是 CrossAug。它针对 chunk 局部抽取系统性遗漏的跨段关系：先挑出"可能缺边"的局部子图，再把子图的实体、已有三元组和证据段落交给 LLM 补全。新三元组必须引用 chunk ID，且只能输出"直接陈述或无歧义支持"的内容，引用不到就丢弃。额外 LLM 调用约为基线的 **8.2%**；抽检 1000 条新三元组，**84.35% 正确**，81.54% 引用准确；把子图选择换成随机后，所有指标下降 ([CrossAug](https://arxiv.org/abs/2605.28004))。它的评估用的是 QA 指标，增益约 1 个 EM 点，没有在金融或中文文本上验证过。落到单篇研报上，流程如下。判重后计算弱连通分量。跨分量的候选节点对走三路召回："名称＋定义"嵌入的 top-k、共享中心词规则、段落邻近（同章节或相邻段）。每次 LLM 调用只传两个分量的节点和边列表（几十行），外加候选节点各自的 2–4 段原文，让模型在四个选项中选一个：SAME_AS、PART_OF、文中明确陈述的跨段因果、无关系。每条输出必须给出段落 ID 和原句摘录，由 Python 校验，引用对不上就丢弃。推断边总数设上限，参照 ai-knowledge-graph，`max_inferred_ratio` 取抽取边数的 0.5 倍。日本的财报因果链检索提供了另一种互补的拼接方式：把一条因果的结果表达和另一条的原因表达做平均词向量余弦匹配，超过阈值就连成链 ([Izumi & Sakaji](https://aclanthology.org/W19-5510.pdf))。Hashimoto 等则要求两段因果在兴奋/抑制方向上兼容才能衔接 ([Hashimoto et al. 2014](https://aclanthology.org/P14-1093/))，对应到这里的格式，就是符号兼容检查。

层级化合并先在章节内（业务分析、盈利预测、估值等）判重和拼接，文档级只处理各章节的规范节点表。这类表通常只有几十到一两百个节点，一次调用就能放下。多级合并会累积误差，因此每一级都只做有证据支持的保守合并。Zep 的增量 map-reduce 摘要会逐渐偏离全量重算的结果，需要定期全量刷新 ([Zep/Graphiti](https://arxiv.org/abs/2501.13956))，跨研报图也一样。

跨研报阶段的原则是"先链接、后合并"。不同研报的相似节点先连 SAME_AS_CANDIDATE 软边，只有多篇报告、多次判定都一致时才提升为合并，这样全局去重的不稳定不会传导回单篇图。边按（A，符号，B）聚合，记录支持研报数、券商数、正负票数和时间跨度。同一对节点符号相反时，保留双方证据，标为"条件依赖"，不用投票抹平。打分可以直接套用两个现成公式。一是哈工大金融事理图谱的转移概率 P(B|A)=f(A,B)/f(A)，只保留共现 ≥5 次的边 ([ELG](https://ar5iv.labs.arxiv.org/html/1907.08015))。二是 FinCARE 的 CompositeScore，即强度、提及频次、公司覆盖度三项的几何平均 ([FinCARE](https://arxiv.org/html/2510.20221v1))；不过 FinCARE 的评估数据由同一套先验生成，增益数字偏乐观。频次统计能否收敛取决于粒度。经济叙事研究在 80 篇文档中得到 409 条不同叙事，大多只出现一次 ([Schmidt et al.](https://arxiv.org/pdf/2506.15041))。这里的节点是变量而不是事件，粒度上更容易收敛，前提是上一节的规范化做到位。最接近的中文先例是 FinKario，它基于东方财富研报，但跨研报只做了名称规范化，没有"事件→财务→估值"的显式链，也没有评估因果有效性，本质上是服务 RAG 的知识图谱，不是因果 DAG ([FinKario](https://arxiv.org/html/2508.00961v1))。表示层面还有一个隐患需要明确：单一正负号默认关系是线性、对称的，无法区分"A 上升导致 B 下降"和"A 下降导致 B 下降"这类非对称情形。Eidos 改用概念状态 ([Eidos](https://par.nsf.gov/servlets/purl/10200912))，经济叙事研究给事件单独标 valence ([Schmidt et al.](https://arxiv.org/pdf/2506.15041))，都是为了解决这个问题。

## 图论只能抓到被覆盖的捷径，缺失中介要靠层级与论断类型

逻辑跳跃有两种，检测手段完全不同。第一种是被覆盖的捷径：报告其他段落已经给出替代路径，例如"归母净利润→公司估值"和"归母净利润→盈利预测→公司估值"并存。第二种是真正缺中介：报告里根本没有"海外销量"节点，"中欧贸易摩擦→公司估值"在图里就是一条没有替代路径的普通边。图论只能处理第一种。对有限 DAG，传递约简是唯一的，它删除所有能由其他路径推出的边 ([Aho, Garey & Ullman 1972](https://doi.org/10.1137/0201008))。networkx 的 `transitive_reduction` 只接受 DAG，研报图里的反馈环要先用 `condensation` 缩成单点 ([networkx](https://networkx.org/documentation/stable/reference/algorithms/generated/networkx.algorithms.dag.transitive_reduction.html))。符号检查可以借用 INDRA 的 `signed_edges_to_signed_nodes()`：把每个变量拆成 (x,+) 和 (x,−) 两个节点，正边同号相连，负边交叉相连，这样普通的有向路径搜索就自动满足"路径符号＝各边符号之积" ([INDRA model checker](https://indra.readthedocs.io/en/stable/modules/explanation/model_checker.html))。单篇研报只有几十个节点，这些计算都在毫秒级。

被覆盖的边不能直接删。按 Pearl 的定义，DAG 中的 X→Y 表示不经过模型中其他变量的直接效应。一旦插入中介 M 又保留 X→Y，它的含义就从总效应变成了绕开 M 的剩余直接效应 ([Pearl 2001](https://arxiv.org/abs/1301.2300))。研报原句"利润增长带动估值提升"多半是对整条链的概括，但也可能对应一个独立机制，比如利润经 PE 直接影响估值，同时又经盈利预测上调影响估值。生物领域有研究在评估 LLM 因果图时，先对 LLM 图取传递闭包再比较，理由正是 LLM 输出常把直接边和祖先边混在一起 ([arXiv 2503.04347](https://arxiv.org/pdf/2503.04347))。合理的处置分两种情况。符号与替代路径一致的覆盖边，降级为 `summary`，可视化时用虚线或隐藏，并记录 `expanded_by`。符号相反的进入复核队列：它要么是真实的对冲机制（如"降价→销量↑"和"降价→毛利率↓"在利润处汇合），要么是抽取错误。

对第二种跳跃，最自然的想法是逐条问 LLM"这条边是不是直接关系"，而这恰恰是 LLM 最弱的一环。Kumar 等用 12 个开源模型、6 个基准因果图测试"是否存在直接边"，模型把 **40.0% 的间接（祖先）非边判成直接边**，这些误判中 **80.8% 给出 ≥80% 的口头置信度**。LLM 的判断偏向召回，改提示词只是在精度和召回之间挪动，消除不了过度预测 ([Kumar et al. 2026](https://arxiv.org/abs/2608.23660))。Vashishtha 等进一步指出，逐对提问在原理上就无法区分直接效应和间接效应，回答者即便是完美专家也一样。他们改用"三元组提问"：给每对变量配一个辅助变量，多次提问后投票；用三元组法的 Phi-3、Llama-3-8B 胜过用成对提示的 GPT-4 ([Vashishtha et al.](https://arxiv.org/abs/2310.15117))。相比之下，LLM 判断成对因果方向很强，在 Tübingen 基准上 GPT-4 的加权准确率达 97% ([Kıcıman et al.](https://arxiv.org/pdf/2305.00050))。也就是说，它擅长判断"有没有关系、朝哪个方向"，不擅长判断"是不是一步到位"。因此，三元组提问只在已有候选中介时使用，例如"在{中欧贸易摩擦，海外销量，公司估值}中，原文所述影响是否经由海外销量？"；检测本身要靠可观测信号。

最便宜的信号在抽取时顺带产生，不增加调用。每条三元组附 `evidence_span`（原文逐字片段）和 `claim_type`。`claim_type` 分四类：机制（原文有"带动/导致/拖累/从而"等传导词，两端是相邻环节）、判断（"考虑到 X，下调目标价/评级/盈利预测"）、风险（风险提示中罗列的因素）、伴随（仅有共变）。这种分法有先例：Yu 等把 PubMed 结论句分为无关系、相关、条件因果、直接因果四类，BERT 分类器准确率 0.90 ([Yu et al. 2019](https://aclanthology.org/D19-1473/))。用论证挖掘的术语说，"考虑到中欧贸易摩擦，下调目标价"是 premise→claim，中间的机制是隐含的 warrant ([Habernal et al. 2018](https://aclanthology.org/N18-1175/))。后续研究发现，BERT 在隐含 warrant 重构任务上的高分来自对"not"等虚假线索的利用，去掉这些线索后接近随机 ([Niven & Kao 2019](https://aclanthology.org/P19-1459/))，所以不要信任模型自由补出的 warrant。FinArg 和 Equity-AMSA 表明，分析师报告中的前提和结论可以分开标注 ([NTCIR-17 FinArg](https://repository.nii.ac.jp/record/2001323/files/01-NTCIR17-OV-FINARG-ChenC.pdf)；[Equity-AMSA](https://aclanthology.org/2024.findings-acl.820))，但目前还没有中文卖方研报的 premise–claim 公开标注集。另加一个布尔字段 `compressed`，标记"明显省略了中间环节"；可选的 `omitted_hint` 只用作检索提示词，不直接入图。抽取提示词应只要求输出"本段明确陈述的直接一跳关系"。通胀叙事图的标注实验中，只标一跳直接原因时，中等档一致性为 **0.441**；含多跳链的完整叙事只有 0.320 ([Huang et al. 2026](https://arxiv.org/html/2603.01930v1))。

第二类信号是节点层级。给每个规范变量分一个层级：宏观政策与外部事件、行业供需与价格、公司经营（销量/产能/单价/成本）、财务科目、预测与估值。边的层级跨度 ≥2（如宏观因素直达估值）就标为疑似跳跃。这套五层划分是工程设计，不是文献标准。如果不想手写，可以从语料里学：在全部研报的规范节点上统计角色比，即出度/(入度＋出度)。经济叙事研究发现，"股市"有 90% 的情况作为结果出现，"政府支出"有 91% 的情况作为原因出现 ([Schmidt et al.](https://arxiv.org/pdf/2506.15041))；同理，"公司估值""归母净利润"会稳定地落在结果端。再结合聚合图中的拓扑深度，就能得到一个连续的、数据驱动的层级分。层级只用于检测，不规定链条：宏观→经营→估值同样是合理的压缩，补哪些中介仍由证据决定。

| 信号 | 能抓到的跳跃 | 额外成本 | 主要误报 |
|---|---|---|---|
| 覆盖边检测（传递约简＋符号积） | 报告内已有替代路径的捷径 | 毫秒级计算 | 真实的直接效应 |
| claim_type ∈ {判断, 风险} | 结论句、风险罗列直连估值 | 抽取时顺带输出 | 分析师确实一步推出的判断 |
| compressed 标记 | 模型自认省略了环节的边 | 抽取时顺带输出 | 模型自评不稳定 |
| 层级跨度 ≥2 | 宏观/行业因素直连财务或估值 | 一次批量层级分类并缓存 | 合理的多层压缩 |

满足任一条件的边即进入下一节的修复队列，多类信号同时命中的边优先处理。

## 修复跳跃：报告内路径优先，语料链条其次，LLM 只做封闭选择

修复按证据强度分三级。第一级是报告内路径：上一节的覆盖边检测已经找到替代路径，直接把原边标为 `summary` 即可。第二级是跨研报聚合图。对跳跃边 (u,v,s)，在有符号节点图上搜索从 (u,+) 到 (v,s) 的 2–4 跳路径，得到的候选天然符号积一致。这个思路有直接先例。Izumi 和 Sakaji 把一条因果的结果表达和另一条的原因表达相连，构成跨文档因果链，既能正向检索波及效应，也能反向检索原因 ([Izumi & Sakaji 2019](https://aclanthology.org/W19-5510.pdf))。ExCAR 从大规模因果事件图中检索原因与结果之间的"证据事件"，用来解释因果判断 ([ExCAR](https://preview.aclanthology.org/fix_video/2021.acl-long.183.pdf))。PRA 把受路径类型约束的随机游走概率作为两个实体之间存在关系的证据 ([Lao & Cohen 2010](https://doi.org/10.1007/s10994-010-5205-8))。Hashimoto 等用"AB＋BC→ABC"拼出 50,000 条情景链，精度 **68%** ([Hashimoto et al. 2014](https://aclanthology.org/P14-1093/))。这是整链精度，意味着约三分之一的拼接链不成立，因此任何来自语料的补全都必须经过核验。

路径打分综合四项：最弱一跳的支持研报数（或各跳支持数的几何平均）、PRA 式转移概率乘积 ∏P(next|cur)、各跳 PMI（防止所有路径都穿过"归母净利润"这类万能枢纽）、长度惩罚。另加层级单调性作为软约束，路径不应从财务层回到行业层。检索范围逐级放宽：本报告 → 同公司历史报告 → 同行业 → 全语料，这样报告独有的逻辑会被优先保留。全局图预计有数万节点、数十万条边，`all_simple_paths(cutoff=4)` 在枢纽节点处会组合爆炸。需要先按支持度剪枝（如 support≥3）并限制枢纽节点的扩展，或改用边权为 −log P 的 `shortest_simple_paths` 取 k 条最短路。AnyBURL 式规则挖掘可以把具体链条泛化成类型级规则，如"外部贸易冲击→海外销量类→利润类" ([AnyBURL](https://www.ijcai.org/proceedings/2019/435))；配合 IS_A 边，"中欧贸易摩擦"就能继承"贸易摩擦"在语料中的典型下游链。NBFNet 这类路径 GNN 能给链接打分并指出重要路径 ([NBFNet](https://arxiv.org/abs/2106.06935))，但它给出的是分数而不是原文证据，只适合作排序特征。COMET 式的生成会造出新节点，与封闭词表的目标冲突，不推荐。

第三级才轮到 LLM，而且它只做受约束的选择和核验。输入是跳跃边、原句、本报告节点表（封闭词表）和第二级检索到的候选路径。输出只有两种：选中一条候选，或者回答"原文不足以分解"。每一跳都要给出符号和本报告中支撑该跳的句子编号，找不到的标为 `background`。Python 复核各跳符号之积是否等于原边符号，不等就拒绝。置信度用多次采样（换温度或换提示）的一致率，不用口头置信。Kumar 等发现，跨提示、跨模型的一致率校准更好，不过经多重校正后差异不显著 ([Kumar et al. 2026](https://arxiv.org/abs/2608.23660))。不让 LLM 自由生成链条，理由很充分。开放式补出缺失变量时，GPT-4o 的输出与真值的平均语义相似度只有 **0.54**，作者也明确说 LLM 无法自评所提变量是否合理 ([Sheth et al.](https://arxiv.org/html/2409.02604))；自由生成的节点名还会制造新的未归一化节点。组合因果推理的错误随路径变长而增加，除 o1 外所有模型都是如此 ([Maasch et al., ICML 2025](https://arxiv.org/html/2503.04556v4))。此前让 LLM 从悬挂节点自由补路径到"公司估值"时，出现了冗余捷径和跳级，正好印证了这些结论。更隐蔽的风险是"经济学上合理，但不是这份研报说的"。有个例子：原文写的是"硬通货流入推高通胀"，GPT-4o 却编码成"货币供应增长推高通胀" ([Schmidt et al.](https://arxiv.org/pdf/2506.15041))。

插入的每一跳都单独核验并分级标注。先用 bge-m3 在本报告句子中检索 top-k 支持句，把"m_i 上升会导致 m_{i+1} 上升/下降"作为假设，交给本地多语言 NLI 模型 ([mDeBERTa-xnli](https://huggingface.co/MoritzLaurer/mDeBERTa-v3-base-xnli-multilingual-nli-2mil7)) 或 MiniCheck 一类轻量核查器判断是否蕴含 ([MiniCheck](https://arxiv.org/abs/2404.10774))，只在 NLI 拿不准时才调用 LLM 判官。判为蕴含的标 `report_supported`；否则查全局图支持度，超过阈值的标 `corpus_supported`；都不满足的标 `llm_inferred`，可视化时用灰色虚线，默认不进入下游统计。被分解的原跳跃边标 `role=summary`，并记录 `expanded_by`。插入链中某一跳如果与报告中的显式边重合，就复用显式边，不新建。传递约简只作用于推断层，这样就不会再出现"利润→估值"和"利润→盈利预测→估值"重复并存。3–5 次的自一致性采样只用于"选哪条候选路径"这一决策，不必每一跳都做。成本与被标记的边数成线性关系，每条边约 1 次主调用加 2–4 次一致性采样，不会像全对查询那样平方级增长。多语言 NLI 对"正向/负向共变"这类因果蕴含的判别能力还没有公开评测，必须用自己的小规模标注集验证。

| 决策 | 选项 A | 选项 B | 建议 |
|---|---|---|---|
| 命名一致性 | 顺序缓存：最一致，但串行，错误会传播 | Pass 1 词表＋并行抽取：多 1 次调用，可并行 | B，再配一次回扫 |
| 不确定的同义对 | 直接合并：图紧凑，错了不可逆 | 软边：节点多，可随时提升为合并 | 单篇内高置信才合并，跨研报一律先连软边 |
| 被覆盖的捷径边 | 传递约简后删除：图干净，丢掉原文陈述 | 标为 summary：保留忠实度 | B |
| 中介候选来源 | 嵌入/GNN 链接预测：召回高，无证据 | 语料统计路径：可溯源，长尾召回低 | 以统计路径为主，GNN 只作排序 |
| LLM 角色 | 自由补链：连通率高，幻觉和跳级多 | 封闭选择＋逐跳核验：保守 | B |
| 证据门槛 | 放宽：大图更连通 | 严格：部分子图保持断开 | 严格，断开本身也是有效信息 |

评估要同时覆盖结构、忠实度和稳定性，全部指标都能用 networkx 计算。估值节点可达率和弱连通分量数，直接衡量"图拼起来没有"。层级跨度超阈值的边占比、覆盖边占比，衡量跳跃率。同一节点对多条路径之间的符号一致性，以及跨研报同一条边的符号一致率，衡量符号可靠性。每条边是否有原文证据、推断边占比，衡量忠实度。重复运行后规范化三元组集合的 Jaccard，作为每次改动的回归指标。人工抽检可以仿照经济叙事研究，区分严重偏差（改变含义、虚构、遗漏）和轻微偏差；那项研究中 GPT-4o 准确率为 44%，专家为 67%–74% ([Schmidt et al.](https://arxiv.org/pdf/2506.15041))。双人标注时用图级 Krippendorff α，并同时报告宽松、中等、严格三档，因为宽松指标会严重高估可靠性 ([Huang et al. 2026](https://arxiv.org/html/2603.01930v1))。落地顺序按投入产出排列。抽取字段（evidence_span、claim_type、compressed、水平量命名）不增加调用，最先做。确定性分块、选择式判定和决策缓存解决结果漂移，其次。覆盖边检测和有符号节点图只是毫秒级计算，紧随其后。带引用的跨分量桥接再往后。跨研报聚合图和基于语料路径的修复，等语料规模大到边频次能够收敛时再上。

## 结论

这两个问题本质上是同一个问题。现在的图只有一种边（正/负因果）和一种节点操作（合并），于是"是同一个东西""是它的一部分""通过它起作用""是对整条链的概括"这四种关系被压进了同一种表示。一旦图能区分身份、组成、机制和概括，合并的问题就从"合得够不够狠"变成"该连哪种边、证据在哪里"；逻辑跳跃也不再是需要删除的错误，而是一条等待展开的概括边。原文的忠实层和补全出来的机制层可以并存，也可以分开统计。"不预设估值骨架"的约束也由此得到满足：由角色比学出的层级，加上由跨研报路径频次学出的典型链，本身就是一副从数据中长出来的骨架，每一跳都能回溯到具体研报句子，并随语料更新而修订。它真正的风险在反方向，即语料共识会悄悄覆盖单篇研报的独到逻辑。所以"报告内路径优先"和"来源分级标注"不是锦上添花，而是整个方案能否被信任的前提。

最大的未知是准确率。上面引用的数字几乎都来自英文、医学、法律或开放域基准，还没有任何公开工作在中文卖方研报上评测过跳跃检测或中介补全。文中出现的每个阈值（0.7、0.8、support≥3、层级跨度≥2），在你的数据上都还没有依据。第一笔投入应该是从自有研报中标注两三百条边，标出是否跳跃、正确的中介是什么、论断类型是什么，用这批标注同时校准判重阈值、层级跳跃阈值和 NLI 核验器，再决定后续哪些模块值得重点投入。
