# 研报估值逻辑图抽取框架设计（v3）

目标：把一篇研报的估值逻辑抽成一张分层的有向图。顶部是公司估值，往下逐层分解到会计科目、经营指标、公司经营情况和外部环境；每条原文边都能指回原文，不同研报在下面三层体现出各自的角度。

## 五层结构

| 层 | 内容 | 例子 | 来源 |
|---|---|---|---|
| 1 公司估值 | 只有一个节点，目标价、评级都并入 | 公司估值 | 预置 |
| 2 会计层 | 固定的会计科目清单，外加“估值倍数” | 归母净利润、营业收入、毛利率、研发费用率、净息差、ROE、估值倍数 | 预置（`research_report/fin_items.py`） |
| 3 经营指标 | 直接构成财务结果的经营量：卖了多少、卖什么价、成本多少、占多大份额 | 销量、海外销量、东盟销量、单车价格、市场份额、产能、汽车业务收入、不良生成率 | 原文 |
| 4 公司经营与行业 | 公司做了什么、有什么、发生了什么，以及公司所在行业和市场的情况 | 匈牙利工厂投产、推出闪充技术、品牌力、客群经营能力；行业竞争强度、欧盟新能源渗透率、竞争对手动作、原材料价格、换机周期 | 原文 |
| 5 外部环境 | 只放宏观和政策层面的因素 | 宏观经济、利率、汇率、资本市场行情、产业政策和法规、补贴和税收政策、关税和贸易政策、地缘政治、原油价格 | 原文 |

分层的判断顺序：是宏观经济、金融市场、政策法规、贸易政策或地缘政治因素 → 第 5 层；是本公司直接构成财务结果的经营量 → 第 3 层；其余（公司自身的情况，以及行业、市场、竞争对手、上下游的情况）→ 第 4 层。主体不是本公司不等于外部环境，拿不准是行业因素还是宏观因素时放第 4 层。分部、地区、产品口径的收入和毛利率放第 3 层，第 2 层只放公司整体口径。

### 预置部分

- **会计层清单**（约 35 项）：损益类、现金流与回报、银行科目。同一科目的金额和比率合成一个节点（“研发费用率”也代表研发费用），别名表负责把“营收”“盈利预测”“归母净利润增速”等说法归到规范名。
- **估值倍数**：不是会计科目，代表折现率、风险溢价和长期成长预期，用来承接“确定性溢价”“行业成长空间”“给予 24 倍 PE”这类影响倍数而不是利润的因素。
- **科目之间的关系**：刻意做浅，大多直接连到归母净利润，避免出现一长串原文没提过的中间科目。银行：净息差 → 净利息收入 → 营业收入 ← 非息收入 ← 手续费、其他非息。
- **到估值的边**：归母净利润、自由现金流、ROE、分红、EBITDA、估值倍数 → 公司估值。PE、PB、DCF 等估值框架的差别只体现在保留下来的是哪些科目，不需要按行业另设骨架。

## 设计原则

1. **前两层固定，后三层灵活。** 会计层和估值的连接预先确定，保证不同研报顶层可比；第 3-5 层的概念和连接来自原文，不同研报可以不同。
2. **方向单调，层层递进。** 边只能从层号大的指向层号小的（可以跨层），同层之间的关系只来自原文。与层级方向相反的原文关系记为反向关系，不进图。
3. **原文优先，逻辑补全尽可能少、只做闭集选择。** 已经能沿原文关系走到估值的概念不再补全，只给走不到估值的子图补边：先找原文；原文确实没写时，只给子图的终点各补一条逻辑边，由大模型从主图中更上层的概念和会计科目中选，不造新概念，并单独标注。
4. **能由程序核对的，不交给模型判断。** 引文是否出自原文、名称是否在表中、层级方向、是否成环，都由程序检查。

## 流程

主流程在 `research_report/report_logic.py`，各步的实现在 `research_report/logic/` 下（base：大模型调用、缓存和校验工具；extract：第 1、2 步；graph：包含关系缩减、建图、剪枝；complete：第 3 步；output：第 5、6 步）。提示词在 `research_report/prompts/report_logic_prompt.md`，几段 prompt 共用的规则写成“共用-”开头的节、只写一处；预置清单在 `research_report/fin_items.py`，可视化在 `research_report/plot_report_logic.py`。

大模型调用共 7 类：建表、整理、抽取、并列、悬挂、补全、归一。

| 步骤 | 输入 → 输出 | 由谁完成 |
|---|---|---|
| 0 正文抽取 | PDF → 段落（`research_report/report_text.py`） | 程序 |
| 1 概念分层填表 | 全文分块 → 概念表（规范名、别名、定义、层级、类型）；逐段抽取之后整理概念表：并入新概念、整理第 3-5 层同一层概念之间的包含关系（一次调用） | 大模型 + 程序校验 |
| 2 原文连边 | 段落 + 概念表 + 会计层清单 → 带原文片段的一跳关系；悬挂补全；并列复核；按层归类 | 大模型 + 程序校验 |
| 3 子图补全 | 删掉孤立概念；走不到估值的子图每个调用一次 → 原文写明的主图概念（原文边），没写的给每个终点闭集选出一条边（逻辑边） | 大模型 + 程序校验 |
| 4 包含关系缩减与收尾 | 每棵包含关系树只保留最上层的概念；剪掉有更长链路的直连；删掉没有下层概念连入的科目 | 程序 |
| 5 全局去重 | 各篇同一层的概念 → 跨研报统一的名称 | 大模型 |
| 6 输出 | JSON、parquet、HTML | 程序 |

### 1 概念分层填表

- 按顺序分块（每块约 3000 字）读全文，滚动维护概念表。每个概念记规范名、别名、一句定义、层级（3/4/5）、类型（指标/事件/状态，第 3 层一律是指标）。
- 会计科目、估值、目标价、评级、PE/PB 等说法按别名归到预置节点，不进表。
- **命名必须能比大小**：概念是能比较大小、多少、强弱的变量，事件按“发生得越多、推进得越快”理解，这样边的正负才有意义。“结构”“政策”“变化”“格局”“波动”这类分不出大小的说法要改写成具体变量：产品结构 → 高端车型销量占比，出口退税政策 → 出口退税率，贸易政策波动 → 贸易政策不确定性。否则同一个“产品结构”会在一处被标成负向（“结构变化拉低单价”）、在另一处被标成正向（“结构改善提升利润”），造成方向冲突。
- 同一概念与不同概念的判定标准沿用 v2：比率≠绝对额、水平≠增速、部分≠整体、不同地区或口径不同，拿不准就新建。
- **整理概念表**：全篇抽完关系后，每篇调用一次大模型，完成两项任务（v3.3 之前是补表、归并两次调用）。一是把逐段抽取时出现的新概念并入概念表，是已有概念的记为别名、抽取记录里的名称随之换成规范名，否则新建，规则与建表相同（提示词中引用同一节共用规则）。二是在并入新概念之后的表上找包含关系（表要等新概念补进来才完整）。两端都只能用表中的名称，规则里举的例子不一定在本篇的表中；程序核对不合格的带错误说明重做，重试用完时只丢掉不合格的条目。
- **包含关系**：在第 3-5 层同一层的概念之间找，每个概念最多一个上位概念，不跨层，程序检查不成环：
  - 第 3 层为加总或相乘：东盟销量 ⊂ 海外销量 ⊂ 销量；东盟市场份额 ⊂ 东盟销量（销量 = 市场规模 × 份额）；占比挂在分子下（出口销量占比 ⊂ 出口销量）。
  - 第 4、5 层为细分：地区、品类、客群或口径更窄的同类因素，或某个因素的具体度量、具体事件。如东盟新能源渗透率、欧盟新能源销量 ⊂ 海外新能源需求；价格战强度 ⊂ 行业竞争强度；匈牙利工厂投产 ⊂ 海外基地建设；欧盟 PHEV 关税税率 ⊂ 欧盟关税税率。
  - 不算包含：只有因果关系的（充电设施影响补能效率）、并列的部分之间、口径不同的量、公司自身情况与行业情况之间。
  - 起因：v3.2 只在第 3 层整理上位指标，第 4 层的各地区需求、渗透率（东盟、欧盟、越南新能源渗透率，海外新能源需求……）平铺在同一层，每个都要单独补一条边。
- 包含关系在第 4 步缩减；在那之前的各阶段图里画成灰色点线（下位 ⊂ 上位）。

### 2 原文连边

- 每段一次调用，带上概念表、会计层清单、小节标题和前一段末尾。名称只能用概念表或会计层清单里的；表里没有的新概念附层级和定义，抽完后在整理概念表时并入。
- 估值和预测：上调或下调预测 → 对应的会计科目（“盈利预测”即归母净利润）；给予倍数、溢价 → 估值倍数；只说目标价、评级 → 公司估值。
- 程序校验：原文片段出自本段；名称合法；出处为小节标题或前文时引用属实；指向估值倍数或公司估值时片段中有相应字样。不合格的附上错误说明重抽。
- 按两端的层级归类：

| 情况 | 处理 |
|---|---|
| 层号大 → 层号小，或同在第 3-5 层 | 进图（extracted） |
| 层号小 → 层号大 | 反向关系，不进图，记录在输出里 |
| 两端都是会计科目，或会计科目 → 估值 | 不新建边；与预置关系同向的，作为该关系的原文证据 |
| 第 3-5 层概念 → 公司估值（如“看好出海，维持买入评级”） | 不连边，作为第 3 步的线索 |

- **并列复核**：逐段抽取时模型常把同一原因的几个结果、或同一句里并列的事项抽成因果。例如“在新车型上市和电池产能突破的共同作用下，国内销量有望回升，并有望优化产品结构、提升单车收入”，曾被抽成“国内销量 → 单车收入”。抽取 prompt 要求每条关系都能指出原文中的因果表述（带动、推动、使得、受益于……），只用“并”“以及”“和”连接的算并列；抽完后，再把要进图的原文关系按研报分批（每批 12 条），连同所在段落交给大模型逐条判断“因果 / 并列 / 拿不准”，判为并列的删掉（记在输出的 `parallel_relations` 里），其余保留。复核在向上合并之前做，用的是合并前的名称。
- 缺影响因素的悬挂记录（如“考虑到以上因素，我们下调盈利预测”）：被影响因素在本篇已有入边时直接并入，否则到同一小节前两段和提到它的段落里找，逐字引用、程序核对。缺被影响因素的记录交给第 3 步。

### 3 子图补全

- **先删孤立概念**：第 1、2 步和向上合并之后，图中没有任何边的概念是孤立的单个节点，不做补全，直接删掉（并入孤立节点的下位指标一并删掉），记在输出的 `isolated_concepts` 里。原文只说它影响估值、或没写明影响对象的概念（如“AI 在物理世界落地的成长动能……维持优于大市评级”），如果没有任何边，同样算孤立；这类线索只在概念本身已在子图里时，供补全参考。
- **处理对象**：主图是沿边能走到公司估值的部分。已经接入主图的概念不再补全，经同层原文关系接入的也算（如“海外销量 → 出口销量占比 → 营业收入”中，海外销量不再单独补一条到营业收入的边）。只处理走不到估值的概念，按弱连通分成子图。不能只看子图和主图是否弱连通：子图常和主图共用上游因素（如某项关税既影响主图里的毛利率，又影响子图里的海外销量），但子图本身没有一条边通往估值。
- **最少补边**：子图里的概念只指向子图内部，所以每个“终点”（子图中不再影响其他概念的概念）都至少要补一条出边；反过来，终点都接上后，子图里的概念都能沿原文关系走到估值。因此逻辑补全只给终点补，每个终点一条，这是让所有概念走到估值所需的最少边数。
- **顺序**：按子图最上面一层是第 3、4、5 层的顺序处理，先接入的子图可以作为后面子图的连接对象。
- **节点在第 2 步结束时确定**：会计层只保留本篇原文抽取记录（含只写了一端的悬挂记录）中出现过的科目和估值倍数，以及从它们沿预置关系通往估值要经过的科目（如原文只提到营业收入时，保留营业收入 → 归母净利润 → 公司估值这条预置路径）；其余预置科目在补全之前就删掉。补全只在这些已有的节点之间连边，不引入原文没有出现的科目。主图中没有比某个终点更上层的节点可连时，这个终点保持走不到估值。
- **候选**：主图中已经连到估值、比影响因素更上层（层号更小）的概念和会计科目，按层列出、紧邻的上一层在前。原文边只从下层指向上层或同层，比影响因素更上层的节点不可能是它的上游，所以补的边不会成环。
- **每个子图一次调用**（v3.3 之前分“先找原文、再按逻辑”两次调用）：附上子图中概念的线索所在段落、子图内部原文关系所在的段落和提到这些概念的段落（终点在前，各带后一段，最多 8 段），让大模型在同一次调用里补两种边。
  - **原文边**：原文写明的“子图中某个概念 → 主图概念”，最多 2 条，附引文，逐字核对，记为跨段原文边（bridged）。
  - **逻辑边**：没有原文边的终点，各选出它最直接影响的 1 个候选，先在紧邻的上一层里找；同属一个分解的并列因子之间不连边（营业收入 = 销量 × 单车价格，销量不影响单车价格）；给出方向和一句理由，不附引文，记为逻辑补全边（logic）。
  - 程序检查：带引文的按原文边核对；不带引文的只能从终点出发，每个终点恰好一条，已有原文边的终点不再补；被影响的一端都要在候选中且更上层。不满足的带错误说明重做。同一层里原文边先加入图、逻辑边后加入。跨两层以上的逻辑补全边单独计数，方便检查。

### 4 包含关系缩减与收尾

1. **包含关系缩减**：解决“销量类、需求类概念平铺在同一层”的重叠问题。逐个看每个有上位概念的概念：
   - 向上只连出一条包含关系（除了包含关系没有别的出边，只被别的概念影响或没有边）：并入上位概念，指向它的原文关系都改连到上位概念（边的说明里记下“合并前：X → Y”）。上位概念自己也只有包含关系出边时继续往上并，直到最上层或遇到不并入的概念。并入的下位概念列在节点详情里。
   - 除了包含关系还有别的出边（进图的原文边，包括同层的边）：去掉包含关系，保留原文边，这个概念自己留在图中，并入它的下位概念也停在它这里。缩减之前的阶段图里，这类包含关系画成淡色、标“⊂✕”。
   - 判断用第 2 步结束时的原文边，不看补全的边：补全在缩减后的图上做，先定下哪些概念并入，才能知道哪些子图走不到估值。
   - 树内部剩下的关系（如上位概念指向并入它的下位概念）去掉。
   - 补全在缩减后的图上计算：同一棵树里只要有一个概念连到估值，整棵树都算连上，补全的边从最上层的概念出发。否则上位概念自己没有出边时也会被补一条，缩减后它继承了下位概念的出边，这条逻辑边就多余了。所以程序里缩减的结果在补全之前就算好，页面上按“补全 → 缩减”的顺序展示。
2. 预置的会计层（原文中出现过的科目、科目之间的关系、到估值的边）和缩减后的原文边合成一张图；补全后再查一次环，先删逻辑补全边。
3. **剪枝**：任意两个节点之间既有直连、又有方向一致、且第一步就走到更上层的更长链路时，删掉直连，其余链路都保留，不论各段是哪类边。更长的链路第一步走的是同层节点时（如 海外销量 → 出口销量占比 → 营业收入），直连保留：下层概念直接接入上层，同层链路只是补充。删掉这样的直连不改变任何两点之间的可达性和可能的方向。被删的直连连同一条代替它的链路记在输出里。例如“新能源车销量”在逻辑补全时同时选了“营业收入”和“归母净利润”，因为有“新能源车销量 → 营业收入 → 归母净利润”，直连归母净利润的那条被删掉。
   - 更长的链路只有方向相反的，直连保留，边上记下那条链路（`conflict_path`），页面上用 ⚠ 标出。这种冲突要么是某条边的方向抽错了，要么是真的两个渠道（如“欧盟插混反补贴税”直接压低单车盈利，又经“本地化产能建设”提升单车盈利）；删掉直连会让净影响翻转，所以留给人工判断。
4. **删掉会计科目**：反复删掉没有任何入边的会计科目（含估值倍数），直到不再变化。留下的科目都有下层概念直接或经由其他科目连入；原文提到、但没有任何概念连入的科目也会删掉。

### 5 全局去重

沿用 v2：所有研报的图建好后，用“名称：定义”的 BGE 向量取近邻和名称互相包含的作为候选对，大模型判断是否同一种概念，并查集合并；同一篇研报里的两个概念不合并；只加全局名称，不改图的结构。v3 只比较同一层的概念，会计层和估值天然一致、不参与。

## 边的类型

| origin | 含义 | 原文证据 | 画法 |
|---|---|---|---|
| extracted | 段内原文 | 有，程序核对 | 实线 |
| bridged | 跨段原文（悬挂补全，或子图补全的原文边） | 有，程序核对 | 点划线 |
| logic | 逻辑补全（子图补全的逻辑边，每个终点一条） | 无，附理由 | 虚线，可在页面上隐藏 |
| preset | 预置的会计关系和到估值的边 | 原文说到时附上 | 灰色细实线 |
| part_of | 包含关系（下位概念 → 上位概念，只在缩减之前的阶段图中） | 无，附关系类型和理由 | 灰色点线 |

## 输出

- `report_graphs.json`：每篇研报的节点（层级、类型、是否接入、净影响、定义、别名、并入的下位概念、原文线索）、边、反向关系、对不上预置关系的会计科目关系、剪掉的直连、删掉的孤立概念和会计科目、概念表，以及全局名称表；`stages` 里另存缩减之前三个阶段的图（概念分层、原文连边、补全）。
- `edges.parquet`、`nodes.parquet`、`relations.parquet`：扁平表，带层级列。
- `report_logic_graphs.html`：五层分层图，左侧标层名。图上方可以切换四个阶段：
  1. 概念分层：第 1 步的概念表，各概念按层排列，灰色点线为包含关系，还没有连边；
  2. 原文连边：缩减之前的原文边和包含关系，孤立概念已删掉，会计层只有原文中出现过的科目，此后节点不再增加；
  3. 补全：节点和第 2 阶段相同，只加上子图补全的边（从包含关系树最上层的概念出发）；
  4. 包含关系缩减（最终）：缩减、剪枝、删掉会计科目之后的结果。
  前三个阶段里，概念是否连到估值、净影响按它所在的包含关系树判断（上位概念经下位概念的边连到估值也算）。
- 指标：补全前后概念连到估值的比例、走不到估值的子图数、补全后仍未连到估值的概念数、各类边数、跨两层以上的逻辑补全边数、反向关系数、剔除的科目数。

  - 之后修改缩减规则：向上只连出一条包含关系的概念并入上位概念；除了包含关系还有别的出边的，去掉包含关系、保留原文边，不并入上位概念。重跑后，47 个下位概念并入上位概念，20 个因另有出边而去掉包含关系。例如中金比亚迪深度：“拉美新能源需求”“海外新能源渗透率”原文都直接写了影响海外销量，现在作为独立节点保留这条边，不再并入“海外新能源需求”；“巴西市场销量 → 出口销量占比”“高端车型销量占比 → 归母净利润”也都保留下来。概念从 186 个增至 203 个，逻辑补全从 38 条增至 44 条（独立出来的概念有的走不到估值，需要补边），总边数 310 条，方向冲突 0 条。这条规则也部分缓解了下面“合并的代价”：有自己出边的下位概念不再把出边算到上位概念头上。
  - 合并的代价：下位概念的出边都算到最上层概念头上。像“出口销量占比 → 毛利率”（结构效应）会变成“销量 → 毛利率”；占比、份额、单价这类通过相乘关系并入的指标，语义损失最明显。
- **v3.3（2026-11-11）**：简化代码和流程，提示词的规则一条不删，只合并。
  - 代码从一个 1734 行的文件拆到 `research_report/logic/` 下，主流程只剩按顺序调用；各步共用“缓存 + 调用 + 校验重试 + 并行”的写法，每篇研报的数据放在一个对象里，不再是十几个按研报编号索引的字典。总行数基本没变。先做了不改变行为的重构：用缓存重跑零调用，JSON、parquet、页面与 v3.2 逐字一致。
